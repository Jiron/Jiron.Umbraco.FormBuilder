# Ligata.Forms: what to port

The owner's earlier forms package, read for ROADMAP step 1.1. It is a read-only reference (CLAUDE.md rule 5):
code may be copied and adapted, nothing is built or run there.

- **Version read:** 0.3.2, commit `8f4b0c5` (only on `origin/main` there; the checked-out `main` is 0.2.1). It was
  exported with `git archive` into `%TEMP%\jfb-ligata-forms-0.3.2` and read from there: 46 files, about 2,500
  lines.
- **Shape:** one Razor class library for Umbraco 17.6.2 and .NET 10, with three tables, a hosted worker, a public
  API under `/api/ligata-forms`, a management API, a dashboard in the Content section, a picker property editor,
  and a framework-free website script. SQLite and a single server are the tested setup.
- **Clean room:** its README and three docs name another product in several places, including links to that
  product's documentation. None of those mentions, links or names are carried into Jiron Form Builder (ROADMAP
  §3.1). Its docs are not copied either; Jiron Form Builder writes its own (Phase 17).

Decisions below: **port** (copy the code or logic and adapt it), **rewrite** (keep the behaviour, write it anew in
Jiron Form Builder's structure), **drop** (not wanted). "Step" means a step of ROADMAP.md.

## 3. Lessons that apply across steps

Already in ROADMAP §3.2 and confirmed by the code: define "empty" explicitly, rate limits must not fail open, no
process-wide locks, searchable data stored as data, DTOs instead of rows, the UI follows permissions, explicit NPoco
column names, test assets under `dotnet run` and after `dotnet publish`, localise every message, layout controls
for sites, registries instead of `switch` statements.

New from the code and its release notes:

- **Look up a replay before spending one-time tokens.** An identical retry must succeed even though its captcha
  token was used up by the first attempt (6.1, 7.2).
- **"Sent" means accepted by the mail server.** The deliveries screen says so, and an uncertain send warns that a
  retry may deliver twice (8.1, 11.2, 12.4b).
- **Restoring an old database brings back old pending mail.** A host switch that pauses sending, shown on the
  dashboard and in the health check, lets an administrator reconcile first (see section 4).
- **Forwarded headers decide the same-origin check** behind a TLS proxy. Without them, every same-origin post from
  an https page looks cross-origin (`troubleshooting.md`, 17.2b).
- **Deterministic markup.** Element ids derive from the form and the per-request instance number, never from
  randomness, so a page renders the same twice (6.2).
- **A button never changes what it does behind the visitor's back.** A fallback or secondary action must not
  silently turn into a submission when the connection comes back (6.4).
- **Lit select fields need their options before their value**, and list editors commit on `change` (9.4).
- **Native HTML drag and drop failed** in the real backoffice; pointer capture worked (1.2a, ADR-0016).
- **Never log provider exceptions**: they can contain personal data and credentials (8.1, 8.2).

## 4. Ideas for the roadmap

Recorded in the feature catalogue (`docs/research/feature-catalogue.md`), each with the step that takes it:

- a host switch that pauses outgoing mail and action runs without losing them (for restores and incidents);
- the "a retry may deliver twice" warning on uncertain runs;
- the open point about where fresh markup comes from after `form_changed` (ADR-0004, 1.4).
